# 収益重視の構成と採用条件

収益改善の判定を、星数や生の価格差の合計から、初期リスクRとコスト込みの時系列評価へ移す構成です。現時点で利益向上が実証された新戦略はありません。安全性・計測の修正を実装し、新しい選抜条件は比較観測に限定します。

## 実装した構成

| 層 | 動作 | 期待効果 | 副作用・限界 |
|---|---|---|---|
| 初期リスク | 初期SLをエントリー時のATR幅で固定。トレーリングはTP到達後 | 指値より有利側にSLが置かれ、数量が過大になる不具合を解消 | 従来のChandelier初期SLより広くなる場合があり、同じリスク予算では数量が減る。利益改善の証明ではない |
| 注文整合性 | LONG: SL < 指値 < TP、SHORTは逆。期限切れを約定判定より先に処理 | 成立しない注文と期限後の架空約定を除去 | 毎時の中値観測では実際の約定時刻や経路が分からない。SLを飛び越えた観測は未確認として取消 |
| 資金配分 | スプレッド、滑り、手数料を損切り想定額に含め、全保有と通貨方向ごとのリスクを制限 | 複数の対円ロングにリスクが集中するのを抑える | 新規数量・取引機会が減る場合がある。急変時に損失が上限内に収まる保証はない |
| 記録 | 注文時のコスト推定、初期SL、戦略版、gross R、推定net R、推定円損益を保存 | 後から動いたSLや最新スプレッドで過去成績を改変しない | 実口座の照合前。スワップは未計上 |
| 成績 | 初期SLが欠損/不正な取引をR評価と信頼度学習から除外。週次スナップショットにも評価を追加 | 異なる通貨ペアを同じRで比較できる | 過去の一部取引は評価不能。保存済みの旧週次集計は再解釈が必要 |
| 候補検証 | pair×方向のコスト後成績と時系列比較を表示。選抜はshadowのみ | 過剰なフィルタや偶然の勝率から本番ルールを決めない | 新たな売買シグナルの優位性や多重検定補正は未実証。自動昇格しない |

## 設定

`profitability_config.json` を読みます。追加の有料APIや外部サービスは必要ありません。

| 設定 | 初期値 | 意味 |
|---|---:|---|
| selection_mode | shadow | 比較評価のみ。live値は拒否する |
| broker_costs_verified | false | ブローカーの実約定・手数料を未照合 |
| slippage_pips_per_side | 0.2 | 片道の仮定滑り。実測値ではない |
| commission_pips_round_trip | 0.0 | 往復手数料の仮定。業者・口座条件と照合が必要 |
| adverse_spread_multiplier | 2.0 | 不利シナリオのスプレッド倍率 |
| adverse_slippage_multiplier | 3.0 | 不利シナリオの滑り倍率 |
| max_total_open_risk_pct | 6.0 | 保有全体の初期損切り想定額上限（残高比） |
| max_currency_direction_risk_pct | 3.0 | 同じ通貨を同方向に保有するリスクの合計上限 |
| min_cohort_trades | 30 | 同じペア・売買方向を比較選抜に使う最低件数 |
| min_walk_forward_train_trades | 30 | 時系列比較前に必要な決済数 |
| walk_forward_folds | 3 | 拡大学習窓で比較する区間数 |
| min_walk_forward_test_trades | 10 | 各比較区間に必要な最低件数 |

6%/3%は選んだ設計上のリスク上限で、最適化した値ではありません。既存の1取引リスク3%を増額せず、合計を2取引分・同一通貨方向を1取引分に制限します。逆方向の建玉でリスクを相殺しません。最小数量に届かない建玉は記録せず、既存建玉の数量や換算価格が不明なら新規リスクを追加しません。

1往復の推定コスト = スプレッド1回分 + 片道滑り×2 + 往復手数料。中値で記録するペーパー建玉に適用します。ブローカーのASK/BID約定にそのまま二重適用してはいけません。

新しい建玉の仮想口座増減には推定コスト後の円損益を使います。旧建玉の`pnl_jpy`と旧残高は価格差ベースの記録で、過去の残高を遡って修復していません。実口座残高の代用や確定した純利益としては扱えません。

## 再現・確認

リポジトリ直下で実行します。報告用スクリプトはネットワーク・通知・実発注を使いません。

```powershell
rtk proxy python -B -X utf8 -m unittest discover -s tests -p test_profitability.py -v
rtk proxy python -B -X utf8 test_spread_monitor.py
rtk proxy python -B -X utf8 test_entry_validator.py
rtk proxy python -B -X utf8 run_profitability_report.py
```

保存済みスキャン時刻より前に決済した取引だけを使い、入力ファイルのSHA-256を報告へ保存します。通常スキャンでも`docs/profitability_report.json`を更新し、`docs/profitability.html`から確認できます。

比較区間の最初のエントリー以前に決済していない取引は学習から除きます。学習データの通常・不利コスト後の平均Rがともに正で、同一ペア・方向の件数を満たした場合だけ、比較選抜群に入れます。この比較は旧ルールの決済記録を選抜したものです。今回修正した初期SL・リスク配分の収益効果を証明するバックテストではありません。

## 初期SLの過去価格による部品試験

2026-10-01にDukascopyの2016〜2025年の日足BID/ASKを10ペア、26,068本取得し、事前固定した[EXP-005](../research/initial_stop_protocol_20261001.md)を実施しました。2017〜2021年を基準期間、2022〜2025年を年ごとの擬似OOSとし、同一のTAエントリーとOCO出口で旧Chandelier初期SLと固定ATR初期SLを比較しています。

OOSの固定ATR案2,511取引は通常コスト後で平均−0.02884R、PF 0.914、悪化コスト後で平均−0.05572R、PF 0.838でした。旧方式より損失を縮めていますが、4検証年すべてで候補の収支はマイナスで、利益増加戦略としての採用条件は不通過です。[年度別の結果・原価格の出典・再現方法](../research/results/2026-10-01-initial-stop-backtest.md)を保存しています。

この試験の1Rはコスト込み予定損失で、台帳監査の初期SL値幅だけの1Rとは分母が異なります。FA・ニュース・指値・TP後トレーリング・同一通貨リスク上限を省いた部品試験のため、本番全体の改善を実証した結果としては扱いません。採用はHOLDです。

## 本番の戦略変更を検討する条件

1. 実約定、数量、初期SL、決済、手数料、滑り、スワップをブローカー履歴と照合する。
2. 変更後のルールと同じエントリー・出口・リスク配分を再現するOHLC/約定データで、事前固定した候補を複数の時系列OOS区間で比較する。
3. 同じリスク予算で基準戦略よりコスト後の期待値が改善し、不利コスト後も正であること。ドローダウン、取引数、期間の偏りも確認する。
4. 調べた候補数を記録し、多重検定調整と独立した再検証を通す。条件を満たすまではHOLD。

通常/不利コストの両方で負の成績を、勝率や★の増額で埋め合わせる設計にはしません。根拠が不足している候補は評価用に残し、改善が確認できた候補だけを別の変更として検討します。
